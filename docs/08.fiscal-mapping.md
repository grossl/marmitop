# 08. Fiscal mapping — from a Marmitop order to a `web-nf` invoice

This document replaces the goal's `08.validation-templates.md` (ADR-013). Marmitop has no municipality template system. This file defines how an order becomes a `POST /v1/invoices` request, which checks Marmitop runs first, and how each `web-nf` error becomes a pt-BR message in the UI.

Requirements covered: FR-120 to FR-139 (invoices), FR-050 to FR-059 (menu fiscal overrides), FR-080 to FR-099 (fiscal settings). Decisions: ADR-003, ADR-006, ADR-012, ADR-013, ADR-016.

Source of truth for the request shape: `web-nf/packages/schemas/src/invoices/` (`nfce.ts`, `nfe.ts`, `invoice-create.ts`, `address.ts`) and `web-nf/docs/06.api-spec.md`. If this file and those schemas disagree, the schemas win. Domain background is in 03.

## 1. Scope

* NFC-e (`kind: "nfce"`) is the default for every order.
* NFe (`kind: "nfe"`) is available when the customer has a CNPJ and the attendant selects "NF-e".
* NFSe is out of scope (ADR-003).

The code that builds the request is a pure function in `packages/core`: `buildInvoiceRequest(order, items, customer, fiscalConfig, menuItems, kind)`. It returns either a request object or a list of field problems. It does no I/O, so it is unit-tested against fixtures (`// covers FR-120`).

## 2. The `web-nf` request, as Marmitop sees it

`POST {base_url}/v1/invoices` with headers `Authorization: Bearer nfk_test_…|nfk_live_…` and `Idempotency-Key: <order_invoices.id>`. The response is `202 { id, status: "queued", kind }`.

### 2.1 NFC-e body

| Field | Type and rule |
|---|---|
| `kind` | `"nfce"` |
| `reference` | string, max 255. Marmitop sends the order code, for example `ORD-042`. |
| `nfce.serie` | positive integer |
| `nfce.operacao.natureza` | non-empty string |
| `nfce.operacao.presenca` | `presencial` or `entrega_domicilio` |
| `nfce.destinatario` | optional object. If sent: `nome?`, `endereco?`, and exactly one of `cpf` or `cnpj` (digits only, valid check digits). Required when `presenca = entrega_domicilio`, together with `endereco`. |
| `nfce.itens[]` | at least 1 (see 2.3) |
| `nfce.pagamentos[]` | at least 1: `{ forma, valor, descricao?, prazo? }` |
| `nfce.troco` | optional. Required when payments exceed the item total (Rej 866). Must equal payments minus total (Rej 869). |
| `nfce.informacoes_adicionais` | optional string |

The NFC-e body has no `tipo`, `finalidade`, `consumidor_final`, `indicador_ie`, or `frete`. The kind fixes them. Do not send them.

### 2.2 NFe body

| Field | Type and rule |
|---|---|
| `kind` | `"nfe"` |
| `nfe.serie` | positive integer |
| `nfe.operacao` | `{ natureza, tipo, finalidade, consumidor_final, presenca }`. `tipo` is `saida`. `finalidade` is `normal`. `presenca` is one of `nao_se_aplica`, `presencial`, `internet`, `teleatendimento`, `entrega_domicilio`, `presencial_fora`, `outros`. |
| `nfe.destinatario` | required: `{ cpf or cnpj, nome, endereco, indicador_ie }`. `indicador_ie` is `contribuinte`, `isento`, or `nao_contribuinte`. |
| `nfe.itens[]` | same item shape as NFC-e |
| `nfe.pagamentos[]` | same as NFC-e (no `troco` field) |
| `nfe.frete.modalidade` | `sem_frete`, `emitente`, `destinatario`, `terceiros`, `proprio_remetente`, or `proprio_destinatario` |
| `nfe.informacoes_adicionais` | optional |

### 2.3 Item (`itens[]`)

| Field | Rule |
|---|---|
| `codigo` | non-empty string |
| `descricao` | non-empty string |
| `ncm` | exactly 8 digits |
| `cfop` | exactly 4 digits |
| `unidade` | non-empty string (for example `UN`) |
| `quantidade` | number greater than 0 |
| `valor_unitario` | number in reais, at least 0, at most 2 decimals |
| `impostos.icms` | `{ origem: "0".."8", csosn?: 3 digits, cst?: 2 digits }`. Exactly one of `csosn` or `cst`. |
| `impostos.pis.cst`, `impostos.cofins.cst` | 2 digits |

### 2.4 Address (`endereco`)

`{ logradouro, numero, complemento?, bairro, codigo_municipio (7-digit IBGE), municipio, uf (2 uppercase letters), cep (8 digits) }`. All fields except `complemento` are required.

### 2.5 Payment forms accepted by `web-nf`

`dinheiro`, `cheque`, `cartao_credito`, `cartao_debito`, `credito_loja`, `vale_alimentacao`, `vale_refeicao`, `vale_presente`, `vale_combustivel`, `boleto`, `deposito`, `pix`, `pix_estatico`, `transferencia`, `fidelidade`, `sem_pagamento`, `outros`.

## 3. Field-by-field mapping

Money: Marmitop stores integer cents (ADR-006). `web-nf` takes reais as a JSON number with at most two decimals. The conversion is `cents / 100`, done once in a helper `centsToReais(cents: bigint): number`. The helper never multiplies or adds reais. All sums stay in cents until the last step. Test: `// covers FR-120`, with values such as 1, 10, 1999, and 123456 cents.

### 3.1 Request level

| `web-nf` field | Marmitop source | Rule |
|---|---|---|
| `kind` | attendant choice; default `nfce` | `nfe` only if `customers.cpf_cnpj` is a valid CNPJ (14 digits) |
| `reference` | `orders.code` | |
| `Idempotency-Key` header | `order_invoices.id` | see section 6 |
| `nfce.serie` | `integrations_fiscal.nfce_serie` | must be set |
| `nfe.serie` | `integrations_fiscal.nfe_serie` | must be set |

### 3.2 Operation

| `web-nf` field | Marmitop source | Rule |
|---|---|---|
| NFC-e `operacao.natureza` | constant | `"Venda ao consumidor"` |
| NFe `operacao.natureza` | constant | `"Venda de mercadoria"` |
| NFe `operacao.tipo` | constant | `"saida"` |
| NFe `operacao.finalidade` | constant | `"normal"` |
| NFe `operacao.consumidor_final` | constant | `true` (meals are consumed, not resold) |
| `operacao.presenca` | `orders.fulfillment` | `delivery` gives `entrega_domicilio`. `pickup` gives `presencial`. |
| NFe `frete.modalidade` | `orders.fulfillment` | `delivery` gives `proprio_remetente` (the restaurant delivers). `pickup` gives `sem_frete`. |

### 3.3 Buyer (`destinatario`)

| `web-nf` field | Marmitop source | Rule |
|---|---|---|
| `cpf` / `cnpj` | `customers.cpf_cnpj` | Strip punctuation. 11 digits go to `cpf`, 14 digits go to `cnpj`. Validate check digits first. |
| `nome` | `customers.name` | |
| `endereco.*` | `customers.cep`, `logradouro`, `numero`, `complemento`, `bairro`, `cidade` (as `municipio`), `uf`, `codigo_municipio` | Structured columns (ADR-016). Gap G1 is resolved. |
| NFe `indicador_ie` | none | `"nao_contribuinte"` (gap G2) |

When to send `destinatario` in an NFC-e:

* Delivery order: always. It needs a valid CPF or CNPJ and a complete address. Without them the order cannot be invoiced (see pre-send rule V5).
* Pickup order: send it only if the customer has a valid `cpf_cnpj` and the attendant confirms "CPF na nota". Otherwise omit it. The receipt then reads "CONSUMIDOR NÃO IDENTIFICADO".
* Any order whose total is R$ 10.000,00 or more: identification is mandatory (SEFAZ rule; some states set lower limits). Pre-send rule V6 asks for it.

### 3.4 Items

One `itens[]` entry per `order_items` row. Order items are snapshots (ADR-006), so a later price change does not change the invoice.

| `web-nf` field | Marmitop source | Rule |
|---|---|---|
| `codigo` | `order_items.menu_item_id` | first 8 characters of the UUID without dashes, or the menu item's code when one exists. Must be stable per menu item. |
| `descricao` | `order_items.name` + `size_name` | `"Marmita de frango (Grande)"`; the size part is omitted when null. Max 120 characters (the XML limit is 120; truncate, never fail). |
| `ncm` | `menu_items.ncm`, else default | resolution order in 4.1 |
| `cfop` | `menu_items.cfop`, else default | resolution order in 4.1 |
| `unidade` | constant | `"UN"` |
| `quantidade` | `order_items.qty` | integer greater than 0 |
| `valor_unitario` | `order_items.unit_price_cents` | `centsToReais`. The unit price already includes the size price. |
| `impostos.icms.origem` | constant | `"0"` (gap G3) |
| `impostos.icms.csosn` | derived | 4.2 |
| `impostos.pis.cst`, `impostos.cofins.cst` | `integrations_fiscal.default_pis_cst`, `default_cofins_cst` | defaults `49` |

`order_items.notes` ("sem cebola") goes to no fiscal field. It stays in the order.

Delivery fee: see section 5.

### 3.5 Payments

`orders.payment_method` gives one `pagamentos[]` entry. Marmitop v1 has one payment per order.

| `orders.payment_method` | `forma` | `valor` | `troco` |
|---|---|---|---|
| `pix` | `pix` | `total_cents` | none |
| `cartao_credito` | `cartao_credito` | `total_cents` | none |
| `cartao_debito` | `cartao_debito` | `total_cents` | none |
| `dinheiro`, `change_for_cents` null | `dinheiro` | `total_cents` | none |
| `dinheiro`, `change_for_cents` set | `dinheiro` | `change_for_cents` | `change_for_cents - total_cents` |

Rules: `change_for_cents` must be at least `total_cents` (also checked when the order is created, FR-030–039). When `change_for_cents` equals `total_cents`, treat it as null.

The item total sent to `web-nf` is the sum of `round(quantidade × valor_unitario)` per item, including the delivery fee line (section 5). That sum must equal `orders.total_cents`. Marmitop asserts this before sending (rule V8). If it does not, the order data is inconsistent, and the invoice is blocked.

### 3.6 Additional information

`informacoes_adicionais`: `"Pedido ORD-042"`. Nothing else in v1. Do not put the customer's phone number or notes here; the text is printed on the receipt.

## 4. Fiscal defaults and overrides

### 4.1 Resolution order

For each order item, Marmitop resolves the fiscal values in this order. The first value that exists wins.

1. `menu_items.ncm` and `menu_items.cfop` (override at item level, FR-058).
2. `integrations_fiscal.default_ncm` and `default_cfop` (restaurant default).
3. Built-in fallback by `menu_items.kind`: `meal` gives NCM `21069090` and CFOP `5101`; `drink` gives CFOP `5102`. A drink has no built-in NCM. The restaurant must set one (rule V3).

Because `order_items` is a snapshot, the item row must keep the resolved `ncm` and `cfop` at order time, or Marmitop must read the current `menu_items` row when invoicing. Decision: read the current `menu_items` row and the current `integrations_fiscal` row at invoice time, and freeze the result in `order_invoices.request_payload` (section 6). The invoice then always matches what was sent. If the menu item was deleted since the order, use the fallback and log a warning.

### 4.2 CSOSN

`menu_items` has no CSOSN column. Marmitop derives it:

* If the resolved CFOP is `5405`, CSOSN is `500`.
* Otherwise CSOSN is `integrations_fiscal.default_csosn` (default `102`).

A restaurant outside Simples Nacional needs `cst` instead of `csosn`. v1 supports Simples Nacional only. If `integrations_fiscal.default_csosn` is empty, rule V4 blocks the invoice with a clear message. Regime Normal is a follow-up (open question Q1).

### 4.3 Defaults offered by the Settings screen

| Setting | Suggested default | Note |
|---|---|---|
| NCM | `21069090` | meals |
| CFOP | `5101` | own production |
| CSOSN | `102` | |
| PIS CST | `49` | |
| COFINS CST | `49` | |

These are suggestions. The screen says: "Confirme estes códigos com o seu contador." (03 explains the typical values; they are not verified against a primary source.)

## 5. Delivery fee

`web-nf` rejects freight values on NFC-e (Rej 753), and its NFe body has only `frete.modalidade`, no freight amount. The item total must still match what the customer paid, because payments must cover the total (Rej 866, 869).

Decision (ADR-013): Marmitop sends the delivery fee as an extra item.

| Field | Value |
|---|---|
| `codigo` | `"ENTREGA"` |
| `descricao` | `"Taxa de entrega"` |
| `ncm`, `cfop`, `csosn`, PIS/COFINS | the restaurant defaults (same as a meal) |
| `unidade` | `"UN"` |
| `quantidade` | `1` |
| `valor_unitario` | `centsToReais(orders.delivery_fee_cents)` |

Only when `delivery_fee_cents` is greater than 0.

Risk: some accountants treat the delivery fee as a service (ISS), which NFC-e does not carry. Others fold it into the price of the goods. Open question Q2 asks the product owner to confirm with an accountant. Until then the choice stays behind a setting: `integrations_fiscal.delivery_fee_mode` with values `item` (default) and `none` (do not invoice the fee; the customer sees a mismatch, so `none` also blocks issuing when the fee is greater than 0 and asks the attendant to adjust the order). The column is proposed for 05.

## 6. Idempotency, retries, and state

* One `order_invoices` row per issue attempt. Its `id` is the `Idempotency-Key`.
* A partial unique index allows only one row per `order_id` with status in `queued`, `processing`, `authorized`. A new attempt is possible only after `rejected`, `denied`, `failed`, or `cancelled`. The attendant clicks "Emitir novamente"; Marmitop creates a new row, so the key is new.
* `web-nf` stores the request body hash. The same key with a different body returns `409 idempotency_conflict`. Keys expire after 30 days. To make a job retry safe, Marmitop saves the exact request in `order_invoices.request_payload` (jsonb; proposed for 05) the first time it builds it. Every retry of the same row sends that stored body.
* A replay with the same key and body returns the stored response and the header `Idempotency-Replayed: true`. The worker treats this as success and reads `id` and `status`.
* The worker stores `web-nf`'s invoice `id` in `order_invoices.external_id`. It stores `numero`, `serie`, and `chave_acesso` when the invoice is authorized.
* Transport errors (timeout, 5xx, connection refused): the job retries with backoff. The same key makes the retry safe even if the first call reached `web-nf`.
* Status values from `web-nf`: `received`, `queued`, `processing`, `authorized`, `rejected`, `denied`, `failed`, `cancelled`. Marmitop stores them as received. In the UI, `received`, `queued`, and `processing` all read "Em processamento".
* Webhook (`POST /v1/webhooks/web-nf/{restaurant_id}`) and the poll job both update the row. The update is idempotent: it never moves a final status back to a non-final one.
* Rate limit: `web-nf` limits mutating routes per API key (`429` with `Retry-After`). The worker obeys `Retry-After`.

### 6.1 Files

The XML and PDF links are short-lived signed URLs. The dashboard calls `GET /v1/invoices/{id}` when the user opens the invoice panel and never stores the URLs (ADR-003). `web-nf` documents the PDF as DANFE for NFe and DANFSe for NFSe; it does not name the NFC-e receipt. Treat a missing `files.pdf` as "PDF indisponível" (open question Q4).

### 6.2 Cancel

`POST /v1/invoices/{id}/events` with `{ "type": "cancelamento", "justificativa": "<at least 15 characters>" }` and a new `Idempotency-Key`. The attendant must type a reason; Marmitop checks the length before sending. NFC-e has no "carta de correção"; the UI must not offer it. The NFC-e window is short (commonly 30 minutes), so the cancel button shows a warning after 30 minutes from `authorized_at`.

## 7. Pre-send validation

Marmitop checks these rules before it creates the job. The goal: catch the mistake in Marmitop, in Portuguese, next to the field, instead of after a round trip. `web-nf` repeats the checks, so these are a courtesy and never a security boundary.

| # | Rule | Block message (pt-BR) | Field |
|---|---|---|---|
| V1 | `integrations_fiscal` exists, with `base_url` and an API key | "Configure a integração fiscal em Configurações." | settings |
| V2 | Series set for the chosen kind | "Informe a série da NFC-e em Configurações → Fiscal." | `nfce_serie` / `nfe_serie` |
| V3 | Every item has an 8-digit NCM and a 4-digit CFOP after resolution | "O item «{nome}» está sem NCM. Preencha no cardápio." | menu item |
| V4 | CSOSN resolved (3 digits); PIS and COFINS CST are 2 digits | "Defina os códigos de impostos padrão em Configurações → Fiscal." | settings |
| V5 | Delivery order: customer has a valid CPF or CNPJ and a complete address | "Para entrega, informe CPF/CNPJ e o endereço completo do cliente." | customer |
| V6 | Total is R$ 10.000,00 or more: valid CPF or CNPJ present | "Pedidos acima de R$ 10.000,00 exigem CPF ou CNPJ do cliente." | customer |
| V7 | If `cpf_cnpj` is present: digits only, valid check digits | "CPF/CNPJ inválido." | customer |
| V8 | Sum of item lines (cents) equals `orders.total_cents` | "O total do pedido não confere com os itens. Revise o pedido." | order |
| V9 | `change_for_cents` is null or at least `total_cents` | "O valor para troco é menor que o total." | order |
| V10 | NFe only: valid CNPJ, name, and complete address | "NF-e exige CNPJ, razão social e endereço completo." | customer |
| V11 | Order status allows invoicing (`pronto`, `saiu`, `entregue`; not `cancelado`) | "Só é possível emitir nota de pedidos prontos, em entrega ou entregues." | order |
| V12 | No active invoice for this order (`queued`, `processing`, `authorized`) | "Este pedido já tem uma nota em andamento ou emitida." | order |
| V13 | Quantity is greater than 0 and unit price is at least 0 | "Item com quantidade ou preço inválido." | order |
| V14 | Item total is greater than 0 | "O pedido tem total zero. Não há nota a emitir." | order |

The result of the checks is a list of `{ path, code, message }`, in the same shape as `web-nf`'s `details[]`. The UI maps `path` to the form field.

### 7.1 Data-model gaps (G1, G4, G5, and G6 are resolved in 05 by ADR-016)

| ID | Gap | Proposal |
|---|---|---|
| G1 | **Resolved by ADR-016.** `customers` and `orders` store `cep`, `logradouro`, `numero`, `complemento`, `bairro`, `cidade`, `uf`, and `codigo_municipio`. There is no free-text address column and no CEP lookup in v1. `restaurants` holds `cidade`, `uf`, and `codigo_municipio` as defaults for new addresses. | Applied in 05. | G2 | No IE indicator for NFe buyers. | v1 sends `nao_contribuinte`. A later column `customers.ie_indicator` allows `contribuinte` and `isento`. |

## 8. Error mapping

### 8.1 HTTP-level errors from `web-nf`

`web-nf` returns `{ "error": { "code", "message", "details?" } }`. Marmitop maps by `code`, not by message text.

| HTTP | `error.code` | Meaning | Worker action | Message in the UI (pt-BR) |
|---|---|---|---|---|
| 401 | `unauthorized` | API key wrong or revoked | Stop. No retry. Mark integration `error`. | "A chave de acesso da integração fiscal é inválida. Atualize em Configurações → Fiscal." |
| 403 | `forbidden` | Key lacks the right role | Stop | "A chave da integração fiscal não tem permissão para emitir." |
| 404 | `not_found` | Invoice id unknown or foreign | Stop | "Nota não encontrada no serviço fiscal." |
| 422 | `validation_failed` | Field errors in `details[]` | Stop. Store details. Mark `failed`. | "Dados da nota inválidos:" followed by one line per detail (see 8.2). |
| 422 | `certificate_missing` | No A1 certificate in `web-nf` | Stop | "O certificado digital A1 ainda não foi enviado ao serviço fiscal." |
| 422 | `csc_missing` | No CSC for the current environment (NFC-e) | Stop | "O CSC da NFC-e não está cadastrado para este ambiente (homologação ou produção)." |
| 422 | `municipality_not_supported` | NFSe only | Never expected. Log as a bug. | "Erro interno. Tente novamente ou fale com o suporte." |
| 409 | `idempotency_conflict` | Same key, different body | Stop. Log as a bug (the stored payload should prevent it). | "Esta nota já foi enviada com outros dados. Cancele e emita novamente." |
| 409 | `conflict` | State conflict (for example, event on a non-authorized invoice) | Stop | "A nota não está em um estado que permita esta ação." |
| 429 | `rate_limited` | Over the plan limit | Retry after `Retry-After` | "Muitas emissões em pouco tempo. Tentaremos de novo em instantes." |
| 5xx / timeout | `internal_error` or none | Transient | Retry with backoff, up to the job limit, then `failed` | "O serviço fiscal está indisponível. Tentaremos novamente." |

### 8.2 `validation_failed` details

`details[].path` is relative to the request body root, for example `nfce.itens[0].ncm`. Marmitop maps the path back to the source:

| Path pattern | Source | Message |
|---|---|---|
| `nfce.itens[i].ncm` | menu item of line i | "NCM do item «{nome}» deve ter 8 dígitos." |
| `nfce.itens[i].cfop` | menu item of line i | "CFOP do item «{nome}» deve ter 4 dígitos." |
| `nfce.itens[i].impostos.*` | fiscal settings | "Revise os códigos de impostos em Configurações → Fiscal." |
| `nfce.destinatario.cpf` / `.cnpj` | customer | "CPF/CNPJ do cliente inválido." |
| `nfce.destinatario` | customer | "Entrega exige cliente identificado (CPF ou CNPJ)." |
| `nfce.destinatario.endereco` | customer | "Entrega exige o endereço completo do cliente." |
| `nfce.destinatario.endereco.cep` / `.codigo_municipio` / `.uf` | customer | "CEP, cidade ou UF do cliente inválido." |
| `nfce.troco` | order | "Troco inconsistente com o pagamento." |
| `nfce.serie` | settings | "Série inválida." |
| `nfe.*` | same, with the `nfe` prefix | same messages |
| anything else | none | "Dados da nota inválidos." plus the raw `message`, shown in the detail panel only |

The raw `error.message` and `details` are stored in `order_invoices.error_message` for support. The UI never shows raw English text as the main message.

### 8.3 SEFAZ rejections (arrive as `status: rejected`, with `error: { code, message }`)

`web-nf` reports the government code and text. Marmitop shows a pt-BR hint for known codes and the raw text for all others. These codes come from the `web-nf` research (03 explains them); the first group should not occur if the pre-send rules work, because `web-nf` fixes the fields. Treat their appearance as a bug.

| Code | Cause | Message (pt-BR) |
|---|---|---|
| 716, 717, 718, 789 | Operation or buyer fields invalid | "Erro interno nos dados da operação. Fale com o suporte." |
| 753, 754 | Freight or transporter data | "Erro interno nos dados de frete. Fale com o suporte." |
| 866 | Payments exceed the total, no troco | "O pagamento é maior que o total e falta o troco." |
| 869 | Troco differs from payments minus total | "O troco informado não confere com o pagamento." |
| 539, 204 | Duplicate document | "Esta nota já foi emitida. Consulte o status." (the poll then finds the authorized invoice) |
| 712 | UF does not accept offline emission | "O estado não aceita emissão em contingência." |
| any other | | "A SEFAZ recusou a nota ({código}): {texto}." |

### 8.4 Final states

| `status` | Meaning | UI | Next action |
|---|---|---|---|
| `authorized` | SEFAZ authorized | Green badge "NFC-e emitida", numero, link to XML and PDF | Cancel (within the window) |
| `rejected` | SEFAZ refused; fixable | Red badge "Rejeitada" + message from 8.3 | Fix data, "Emitir novamente" |
| `denied` | SEFAZ denied (irregular issuer registration; NFe) | Red badge "Denegada" + "Regularize o cadastro do emitente na SEFAZ." | Contact accountant. No retry. |
| `failed` | `web-nf` gave up (transient errors exhausted) | Amber badge "Falhou" + "O serviço fiscal não respondeu." | "Emitir novamente" |
| `cancelled` | Cancellation authorized | Grey badge "Cancelada" | none |

## 9. Test plan
